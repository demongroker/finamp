# JellyAmp P0.4 — Codebase Architecture: decompose main.dart

Date: 2026-08-18
Branch: features/jellyamp-1.1
Status: IMPLEMENTED (phase 1 — structural decomposition of the main.dart God file)

## Goal

Per the roadmap, main.dart must not remain a permanent God file. Startup routines,
platform init, database setup, audio init, downloads, migrations, and the app widget
tree should not be tightly coupled. This phase makes main.dart boring and gives startup
dependencies clear ownership, explicit initialization order, explicit failure behavior,
and minimal global mutable state.

## Final lib/ structure

```

  app.dart               NEW: JellyampApp + Finamp + FinampApp (MaterialApp/routes/

```

Only the dirs that genuinely reduce coupling were created (`bootstrap/` + `app.dart`).
`routing/`, `lifecycle/`, `features/`, `services/` were NOT created (deferred — see below).

## Entry point

```dart
Future<void> main(List<String> args, {bool integrationTesting = false, bool loginTesting = false}) async {
  if (loginTesting) {
    final data = await TestingPathProvider.baseDirectory();
    PathProviderPlatform.instance = TestingPathProvider(data);
    if (data.existsSync()) data.deleteSync(recursive: true);
  }
  final dependencies = await _startup(args, integrationTesting: integrationTesting);
  if (dependencies == null) return;
  if (!integrationTesting) {
    runApp(JellyampApp(dependencies: dependencies));
  }
}
```

- `main()` signature unchanged (`List<String> args, {integrationTesting, loginTesting}`) —
  required by `integration_test/test_cases.dart` which calls `app.main([], ...)`.
- `export 'app.dart' show Finamp, FinampScrollBehavior;` keeps `app.Finamp()` and the 3
  component imports of `FinampScrollBehavior` working.

## Init order + failure (preserved byte-identical)

- `bootstrap()` runs every step in the original order (`setupLogging → edgeToEdge →
  setupHive → applyLogLevel → runMigrations → trustAndroidUserCerts →
  installClientCertificate → userHelper → jellyfinApi → offlineListen → downloadsHelper →
  providers → OSIntegration → PlayOn → Playback → KeepScreenOn → DiscordRpc`), emitting
  the exact same `Logger("Main()")` info lines between steps.
- `runMigrations()` preserves the exact migration sequence (downloadLocations → sortOptions →
  gridSize → homescreen → featureChips → deviceId → themeModeLocale), including async awaits
  and `overwriteFinampSettings` semantics.
- Failure behavior identical: try/catch wraps the whole startup; on failure →
  `Logger("ErrorApp").severe` + `runApp(FinampErrorApp(error, trace))` + return; when
  `integrationTesting` → rethrow. Flutter error handlers installed at the same point
  (only when `!integrationTesting`); `DartPluginRegistrant`/`findSystemLocale`/
  `initializeDateFormatting`/`fetchSystemPalette`/`initDBus` run in the same place.

## Deferred

- `routing/`, `lifecycle/`, `features/`, `services/`: not created. Routes are a static const
  map in `FinampApp`; splitting them would introduce a routing module with zero behavioral
  benefit at this stage, and screen-level files already live under `screens/`/`components/`.
  `services/` already exists as a flat dir. These remain available as future structure if
  coupling grows.
