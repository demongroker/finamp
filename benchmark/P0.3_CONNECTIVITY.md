# P0.3 step 7 - ONLINE / DEGRADED / OFFLINE connectivity behavior

Date: 2026-08-18
Branch: features/jellyamp-1.1
Scope: connectivity state model + one subtle global indicator. Additive on
existing signals and the existing manual Offline Mode toggle. Does NOT touch the
P0.2 download state machine / download ownership.

## Goal

Jellyamp must explicitly understand connectivity so that when the server is
unreachable it automatically falls back to the local (downloaded) library and
remains usable - without flooding ordinary screens with network error dialogs,
broken-artwork placeholders, retry popups, or full-screen errors. Per the
roadmap UX rule we surface ONE subtle global state indicator.

Three states (from the roadmap):
- ONLINE   - server communication operating normally.
- DEGRADED - server technically reachable but normal operation unreliable.
- OFFLINE  - Jellyfin cannot currently be reached; auto fall back to local.

## Authoritative state model (single source of truth)

New file: `lib/services/connectivity_state.dart`

- `enum ConnectivityState { online, degraded, offline }`
- `ConnectivityStateNotifier extends Notifier<ConnectivityState>`, exposed as
  `connectivityStateProvider`. Every screen/widget that cares about
  connectivity should read this one provider.
- Built on top of the signals that already exist in the codebase (nothing
  reinvented):
  1. The manual / auto "Offline Mode" setting `FinampSettings.isOffline`
     (`lib/models/finamp_models.dart:478`, driven by
     `lib/services/network_manager.dart` `_setOfflineMode`).
  2. Platform network-interface state from `connectivity_plus`
     (the same package `network_manager.dart` already uses).
  3. Real server request outcomes recorded from the single API choke point
     `JellyfinApiHelper.runInIsolate`
     (`lib/services/jellyfin_api_helper.dart:115-146`) into
     `ServerRequestSignals` (`lib/services/connectivity_state.dart`).

The state is recomputed reactively whenever any of those signals change
(interface stream, request-signal stream, settings stream all watched in
`build()`).

### State derivation (`_computeState`, `lib/services/connectivity_state.dart:176`)

1. If the Offline Mode setting is true and we did not auto-engage it ourselves
   -> OFFLINE. This is the authoritative manual/existing-auto toggle.
2. If the device has no usable network interface (`networkInterfaceDown`) ->
   OFFLINE.
3. No requests observed yet (e.g. at startup) -> ONLINE (assume healthy).
4. All recent requests failed (no success in window) with failures >= 3 ->
   OFFLINE (server unreachable).
5. At least one recent success but failure rate >= 0.5 -> DEGRADED.
6. Otherwise -> ONLINE.

## DEGRADED heuristic

The core principle: DEGRADED is distinguished from OFFLINE by *reachability*,
measured from the mix of real request outcomes, not just from connectivity.

- `ServerRequestSignals` keeps a rolling window (40) of request outcomes
  (`lib/services/connectivity_state.dart:99`).
- `hasRecentSuccess` == at least one successful request in the window. If true,
  the server was reachable recently -> failures are treated as DEGRADED
  (reachable but unreliable) rather than OFFLINE.
- If the whole window is failures (`allRecentFailed`) and there are >= 3
  failures -> OFFLINE (server unreachable).
- Failure-rate threshold for DEGRADED: `degradedFailureRate = 0.5`
  (`lib/services/connectivity_state.dart:31`).
- Timeout vs immediate rejection is recorded as a secondary qualitative signal
  (`_isTimeout`, `lib/services/jellyfin_api_helper.dart:142`); it is logged and
  available but the primary decision is the success/failure mix.

Deliberately simple and principled, not over-engineered: consecutive failures
with no recent success => offline; mixed success/failure => degraded; healthy =>
online. Recovery is automatic (see below), so aggressive classification is safe.

## OFFLINE fallback

- The actual "fall back to local state" behavior already exists and is keyed on
  `FinampSettings.isOffline` (every offline branch in the app reads it). P0.3
  step 7 makes it happen *automatically* when the server is unreachable,
  without requiring the user to manually flip the Offline Mode toggle.
- In `ConnectivityStateNotifier._reconcileOfflineSetting`
  (`lib/services/connectivity_state.dart:202`), when the derived state becomes
  OFFLINE from signals (not from a manual choice), it calls
  `FinampSetters.setIsOffline(true)`. When it becomes ONLINE again and we had
  auto-engaged, it calls `FinampSetters.setIsOffline(false)`.
- Composition with the manual toggle:
  - A manual offline choice is never overridden. The auto-engage is guarded by
    `!FinampSettingsHelper.finampSettings.isOffline`, and auto-recovery only
    happens for `_autoEngagedOffline` (a session flag we set ourselves).
  - If the user has the existing auto-offline automation enabled
    (`AutoOfflineOption != disabled && autoOfflineListenerActive`), that code
    already owns flipping `isOffline` (with its 7s confirmation), so we defer to
    it and only observe. No double-handling / no double snackbars.
  - When the automation is disabled (default), our signal-driven auto fallback
    provides the automatic behavior the roadmap requires.
- Limitation (documented): `_autoEngagedOffline` is in-memory, so if the app is
  killed while offline-engaged, the flag resets on restart and the app will not
  silently flip the user back online; the indicator still reflects real signal
  state. This deliberately avoids surprising users who left Offline Mode on.

## Global indicator (ONE, subtle)

New file: `lib/components/connectivity_status_indicator.dart`

- `ConnectivityStatusIndicator` is a ConsumerWidget reading
  `connectivityStateProvider`. It renders nothing when ONLINE; otherwise a
  single small, rounded, non-interactive status pill at the top-center of the
  app:
  - DEGRADED -> "DEGRADED - Server unreliable"
  - OFFLINE  -> "OFFLINE - Showing downloaded library"
  - ONLINE   -> nothing.
- Wrapped in `IgnorePointer` so it never blocks taps/scrolling; no error
  dialogs, no retry popups, no full-screen errors are added.
- Rendered globally via the existing `MaterialApp.builder` hook:
  `buildAppWithConnectivityIndicator` stacks the pill over
  `buildPlayerSplitScreenScaffold` (so it appears on every route without
  touching any screen's Scaffold). Wired in `lib/main.dart:1028`
  (`builder: buildAppWithConnectivityIndicator`).
- Design-system consistent (no restyle): uses the frozen tokens
  (charcoal `iceBgColor #0B0F14`, ice accent `icePrimaryColor #7DD3FC`,
  highlight `iceHighlightColor #E0F2FE`, spacing/radius tokens from
  `lib/theme/jellyamp_theme.dart` and `lib/color_schemes.g.dart`).
- Labels are currently inline English strings (this is a small technical chip).
  Future localization can move them into l10n arb files; flagged as follow-up.

## OFFLINE-experience features - already covered by existing code

The roadmap's OFFLINE EXPERIENCE list is largely implemented by P0.1/P0.2 code
keyed on `FinampSettings.isOffline`. P0.3 step 7 did NOT re-implement these; it
verified them:

- Downloaded tracks / playback: `lib/services/music_player_background_task.dart`
  (offline handling at :1249, offline queue items at :1337);
  `lib/services/audio_service_helper.dart:64,99,225`; download source via
  `lib/services/downloads_service.dart` (`getTrackInfo` :1686).
- Downloaded albums / playlists (collection tracks):
  `lib/services/album_screen_provider.dart:21-38` (`getAlbumOrPlaylistTracks`
  returns downloaded tracks when offline, incl. playable-vs-all split; playlist
  sorting at :53-102, favorites filter at :90-94).
- Artists: `lib/services/artist_content_provider.dart:26`.
- Search (downloaded-only): `lib/services/radio_service_helper.dart:332`
  (queue filtering keeps only downloaded when offline) and item/amount providers
  `lib/services/item_amount_provider.dart:32,57`.
- Queue: `lib/services/queue_service.dart` (auto-refresh/offline handling at
  :171, :468, :495, :896).
- Downloaded artwork: `lib/services/album_image_provider.dart:104` (downloaded
  image file first) and :124 (returns empty placeholder when offline instead of
  hitting the server -> no broken-artwork floods).
- Technical metadata: `lib/services/item_by_id_provider.dart:26-28`
  (`downloadsService.getCollectionInfo` / `getTrackInfo` fallback);
  `lib/services/downloads_service.dart:1382,1686,1693`.
- Cached favorites: `lib/services/album_screen_provider.dart:90-94` (favorites
  filter applied from cached `userData`); offline menus disable favorite toggles
  (`lib/menus/components/menuEntries/toggle_favorite_menu_entry.dart:20,33`).
- Playback history / listening: `lib/services/playback_history_service.dart`
  (offline guards at :51-52, :360, :417, :470, :485, :507).
- Various menus degrade gracefully offline (disable/hide online-only actions):
  e.g. `lib/services/radio_service_helper.dart:909-935`,
  `lib/menus/components/menuEntries/*`.
