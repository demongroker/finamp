# P0.3 step 8 - Harden local/offline metadata + artwork behavior

Date: 2026-08-18
Branch: features/jellyamp-1.1
Scope: Offline metadata / artwork hardening. Additive and safe; composes with the
P0.3 step 7 connectivity state. Does NOT touch the P0.2 download state machine /
ownership, and does NOT re-architect or re-build the offline library.

## Goal

Per the roadmap OFFLINE EXPERIENCE, downloaded items must resolve their technical
metadata locally (no unnecessary network round-trip when a local copy exists),
downloaded artwork must degrade to a clean placeholder offline (no broken /
full-screen error), and cached favorites / listening state must be served from
local state.

## Audit: how offline metadata + artwork + favorites/history are stored and served today

### Metadata storage (DownloadItem BaseItemDto jsonItem)

- `lib/models/finamp_models.dart` - `DownloadItem` stores the item's technical
  metadata as `jsonItem` (a JSON-encoded `BaseItemDto`). `DownloadItem`/`DownloadStub`
  expose `baseItem` (decoded). Isar schema: `lib/services/downloads_service_backend.dart`.
- `lib/services/downloads_service.dart`:
  - `getTrackInfo` (:1686) / `getCollectionInfo` (:1693) - look up a downloaded
    track/collection by id and return its `DownloadStub` (metadata from `jsonItem`).
  - `getCollectionTracks` (:1382) - offline album/playlist track list from the
    Isar `downloadItems` table (with playable/all split, favorites filter, genre,
    ordered-children playlist ordering).
  - `getAllTracks` (:1433) / `getAllCollections` (:1572) - offline browse queries.
- `lib/services/item_by_id_provider.dart:14-39` - the single metadata-resolution
  provider. When offline (`finampSettingsProvider.isOffline`) it resolves from
  `getCollectionInfo` / `getTrackInfo` (local `jsonItem`); otherwise it calls
  `jellyfinApiHelper.getItemById` (network).

### Artwork storage + serving

- Downloaded artwork is stored as `DownloadItem` rows of type `image`, keyed by
  `blurHash` (fallback `imageId`); files live under
  `FINAMP_BASE_IMAGES_DIRECTORY` (`lib/services/downloads_service_backend.dart`).
- `lib/services/downloads_service.dart:1711-1721` `getImageDownload` - returns the
  verified local image file (`_getDownloadByID` -> `_verifyDownload` checks
  `item.file.existsSync`, :877-880).
- `lib/services/album_image_provider.dart` `albumImageProvider` (family, :76-190):
  1. :104 resolves the local downloaded image first (`getImageDownload`).
  2. :115-121 falls back to the in-memory player image cache.
  3. :123-126 if still null and offline -> `AlbumImageInfo.empty` (no network).
  4. :130-176 otherwise fetches from the server via `getImageUrl` (network).
- `lib/components/album_image.dart` `BareAlbumImage` (:211-269): a null image
  renders the blurHash placeholder (if `blurHash` present, :232-241) else the
  default card-color placeholder; a decode failure hits `errorBuilder`
  -> `_AlbumImageErrorPlaceholder` (album icon, :324-331). So a missing/corrupt
  downloaded artwork already degrades to a clean, non-full-screen placeholder.
- Player-screen theme: `lib/services/theme_provider.dart` `FinampThemeFromImage`
  (:168-206) returns the gray theme when the image is null, so no full-screen
  background error. `BlurredImage` (`lib/components/blurred_image.dart`) is
  currently unused.

### Cached favorites / playback history / listening state

- Favorites are cached locally as a `FinampCollectionType.favorites` row in the
  `downloadItems` table; `downloads_service.dart:1734-1737` `_getFavoriteIds`
  reads it. `isFavorite` (:1729) and the offline favorites filter in
  `getCollectionTracks` / `getAllTracks` (:1407, :1453) serve it locally.
  `album_screen_provider.dart:25-28,90-94` applies the favorites filter offline.
- Playback history / listening state: `lib/services/playback_history_service.dart`
  guards remote reporting offline (:360-363, :417, :470-472, :485-487, :507-509)
  and routes listens to `OfflineListenLogHelper`
  (`lib/services/offline_listen_helper.dart:61-64`, Hive box `"OfflineListens"`).
  History/listening are tracked in local state and flushed when back online.

## Gap identified (and what was hardened)

The offline metadata and artwork paths were keyed ONLY on the
`FinampSettings.isOffline` setting, not on the authoritative connectivity state
from P0.3 step 7 (`connectivityStateProvider`). P0.3 step 7 auto-engages the
`isOffline` setting when the server is detected unreachable, but that reconcile
is asynchronous. In the window where the server is already detected OFFLINE but
`isOffline` has not yet been reconciled - and in any case where signals say OFFLINE
while the setting lags - two unnecessary network behaviors could occur:

1. `albumImageProvider` could still attempt a network art fetch (and then show the
   error placeholder) even though the server is unreachable.
2. `itemByIdProvider` could still hit the network for a downloaded item's technical
   metadata even though the server is unreachable.

These were the highest-value hardening targets: both directly touch the roadmap's
"downloaded items resolve technical metadata locally" and "downloaded artwork
degrades gracefully offline" requirements, both compose cleanly with the step-7
state, and both are strictly additive (no online-behavior change).

## HARDENING FIXES

### Fix 1 - Artwork never fetched from network when connectivity is OFFLINE

- File: `lib/services/album_image_provider.dart` (:123-128).
- Change: the "no local/cached image available" path now treats the item as offline
  when EITHER the `isOffline` setting is set OR the authoritative connectivity state
  is `ConnectivityState.offline`, and returns `AlbumImageInfo.empty` instead of
  attempting a server fetch.
- Why highest-value: closes the step-7 reconcile window so a genuinely unreachable
  server can never trigger a network art fetch; the missing-art case degrades to a
  clean placeholder (blurHash if present, else card-color / album-icon placeholder)
  - no broken or full-screen artwork. Online/DEGRADED behavior is unchanged.

### Fix 2 - Downloaded items resolve technical metadata locally when connectivity is OFFLINE

- File: `lib/services/item_by_id_provider.dart` (:25-34).
- Change: metadata resolution now resolves locally (from `getCollectionInfo` /
  `getTrackInfo`, i.e. the item's own `jsonItem`) when EITHER the `isOffline`
  setting is set OR the authoritative connectivity state is
  `ConnectivityState.offline`; otherwise it fetches from the server as before.
- Why highest-value: guarantees downloaded items resolve their technical metadata
  locally with no unnecessary network round-trip the moment the server is detected
  unreachable, even before the `isOffline` setting reconciles. Online/DEGRADED
  behavior is unchanged.

## ARTWORK DEGRADATION (offline)

Missing / absent downloaded artwork offline now degrades as follows, with no broken
or full-screen error:

- If a downloaded image file exists locally, it is served directly (FileImage, no
  network) - `album_image_provider.dart:104`.
- If the local file is missing or fails to decode, `_verifyDownload` / `errorBuilder`
  catch it and show a clean placeholder: the item's blurHash (if present) else a
  card-color / album-icon placeholder (`album_image.dart:232-241,263,324-331`).
- If no local image exists at all and connectivity is OFFLINE (either setting or
  detected state), `AlbumImageInfo.empty` is returned and the same clean placeholder
  renders (`album_image_provider.dart:123-128`). No network request is made.
- Player-screen background theme falls back to the gray theme on a null image
  (`theme_provider.dart:173-174,188-190`), so no full-screen background error.

## METADATA LOCAL RESOLUTION (offline)

- `itemByIdProvider` now resolves downloaded items' technical metadata locally the
  moment the server is detected OFFLINE, even before the `isOffline` setting
  reconciles (`item_by_id_provider.dart:25-34`).
- Offline browse/search already read local `jsonItem` via `getCollectionTracks`,
  `getAllTracks`, `getAllCollections`, `getTrackInfo`, `getCollectionInfo`.

## CACHED FAVORITES / LISTENING STATE (offline)

Already served from local state (verified, not changed in this step):
- Favorites: `downloads_service.dart:1729,1734-1737,1407,1453`;
  `album_screen_provider.dart:25-28,90-94`.
- Listening/history: `playback_history_service.dart` offline guards;
  `offline_listen_helper.dart` Hive `"OfflineListens"` queue.

- `lib/services/item_by_id_provider.dart` - local metadata resolution composed with

## What remains / limitations

- Offline artwork placeholder is cosmetic: a downloaded item with no blurHash and no
  downloaded art renders a plain card-color / album-icon placeholder. Deliberately
  left as-is to avoid a restyle; it is already clean and non-intrusive.
- `itemByIdProvider` still prefers the server while ONLINE/DEGRADED (fresh metadata),
  which is correct for online freshness; only OFFLINE resolves locally.
- An item with a blurHash but null `imageId` early-returns empty before the local
  image lookup (`album_image_provider.dart:97-99`); in practice Jellyfin supplies
  both together, noted here as a known edge, not changed.
- `_autoEngagedOffline` recovery flag remains in-memory (step-7 limitation).
